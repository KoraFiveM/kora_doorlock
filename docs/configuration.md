# Configuration

Options live in `config.lua`. Some can also be changed from the `kora_lib` configuration panel (marked below). Per-server overrides generated by `kora_lib` are written to `config.local.lua`, which is git-ignored.

## General

| Option | Default | Description |
| --- | --- | --- |
| `Config.Doors` | `{}` | Authored doors, keyed by stable door ID. See [Door definitions](./doors.md). Panel-editable. |
| `Config.InteractionDistance` | `1.8` | Default interaction distance in metres for doors that do not set `distance`. |
| `Config.DefaultAutoLock` | `nil` | Default milliseconds before an unlocked door locks itself. Unset means no auto-lock unless the door has `autoLock`. Panel-editable. |
| `Config.Debug` | `false` | Server prints which access check granted or refused each toggle; client zones are drawn in debug mode. |
| `Config.Notify` | `false` | When true, the server sends a "Door locked" or "Door unlocked" notification to the player who changed the state. |

## Access

| Option | Default | Description |
| --- | --- | --- |
| `Config.UnrestrictedDoorsOpenToAll` | `false` | When false, a door with no `groups`, `items`, `characters` or `passcode` can only be toggled by players with a door ACE (or admins when bypass is on). Panel-editable. |
| `Config.AdminsBypassDoorAccess` | `false` | When true, holders of the admin permission can use every door with the toggle key. Panel-editable. |
| `Config.DoorAceExactOnly` | `true` | When true, door ACEs match only `doorlock.ID` and `doorlock.LABEL`. When false, `group.` and `command.` objects also match. Panel-editable. |
| `Config.PlayerAceAuthorised` | `false` | When true, players holding the permission in `Config.PlayerAcePermission` can use every door. |
| `Config.PlayerAcePermission` | `'doorlock'` | Permission name checked when `PlayerAceAuthorised` is on. |
| `Config.AdminPermission` | `'admin'` | Permission that grants the creator and management callbacks. |
| `Config.AdminPermissionPrefix` | `'kora_core'` | Prefix for the admin permission (`kora_core.admin` by default). |

## Commands

| Option | Default | Description |
| --- | --- | --- |
| `Config.AdminCommand` | `'doorlocks'` | Creator command name. |
| `Config.CreateCommand` | `'adddoor'` | Create-door command name. `newdoor` and `doordebug` are always registered as well. |
| `Config.ImportCommand` | `'importoxdoors'` | `ox_doorlock` import command name. |

## Lockpicking

| Option | Default | Description |
| --- | --- | --- |
| `Config.LockpickItems` | `{ 'lockpick' }` | Item names that count as a lockpick. |
| `Config.CanPickUnlockedDoors` | `false` | Allow picking a door that is already unlocked. |
| `Config.LockpickDifficulty` | `{ 'easy', 'easy', 'medium' }` | Default difficulty for doors without `lockpickDifficulty`: a list of `easy`, `medium`, `hard` or custom entries, or a native table. |
| `Config.LockpickBreakChance` | `{ success = 1, failure = 20 }` | Percent chance the lockpick item is consumed after a successful or failed attempt. |
| `Config.lockpickRateLimit` | `{ max = 4, window = 10000 }` | Lockpick starts allowed per player per window in milliseconds. Panel-editable (advanced). Read when the resource starts. |

## Interface and sounds

| Option | Default | Description |
| --- | --- | --- |
| `Config.DrawTextUI` | `true` | Show the lock or unlock prompt near a door. |
| `Config.ShowDoorNameInPrompt` | `false` | Include the door label in the prompt. Otherwise the generic "Lock Door" or "Unlock Door" text is used. |
| `Config.DrawSprite` | lock icons | Sprite (`dict`, `name`, `width`, `height`, `color`) drawn for `locked` and `unlocked`. Set to nil to disable. Doors with `hideUi` never draw it. |
| `Config.DrawSpriteCentered` | `true` | Draw the icon at the middle of a single door instead of its hinge. Panel-editable. |
| `Config.DrawSpriteOffset` | `vector3(0, 0, 0)` | World offset in metres added to the icon position. Panel-editable. |
| `Config.DefaultSounds` | Keycard sounds | Fallback sound (`name`, `set`) for `locked` and `unlocked`. |
| `Config.IgnoreVehicleDoorSounds` | `true` | Per-door sounds in the sound sets or names below are ignored and the default is used. Stored data is not changed. |
| `Config.VehicleSoundSets` | `PI_Menu_Sounds`, `Vehicle_Alarm_Sounds`, `ALARMS` | Sound sets treated as vehicle sounds. |
| `Config.VehicleSoundNames` | `Remote_Control_Open`, `Remote_Control_Close`, `Remote_Control_Fail`, `Car_Alarm` | Sound names treated as vehicle sounds, case-insensitive. |

Locale strings are in `locales/*.json` (de, en, es, fr, it, nl, pl, pt, ru, tr).
